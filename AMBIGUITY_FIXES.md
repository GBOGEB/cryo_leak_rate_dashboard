### Issue 2: No `<meta name="dashboard-version">` in auto-generated pages — ⚠️ DOCUMENTED

**Problem:** 6 auto-generated triage pages (`dashboard.html`, `executive_summary.html`, `calculations.html`, `rtm_traceability.html`, `handover.html`, `triage_compliance.html`) have no machine-readable version tag.

**Current status:** These files have no `<meta name="dashboard-version">` tag. The only version indicator is text content within the pages.

**Remediation:** Add to `src/generate_dashboard.py` → `_page()` function:
```html
<meta name="dashboard-version" content="{version}"/>
```
**Priority:** 🟢 Medium — add during next rebuild cycle.

### Issue 3: `visualizations_v3/` name implies v3 data — ✅ CLARIFIED

**Problem:** Directory name `visualizations_v3` suggests v3.0 data, but 4 charts contain v4.0.0 compressor data (updated 2026-05-10), while 17 others are pure physics charts independent of version.

**Remediation:** 
- Added `docs/visualizations_v3/README.md` explaining the naming convention ✅
- The "v3" in the directory name refers to the **generator version** (`generate_visuals_v3.py`), not the data version
- **No rename needed** — renaming would break existing links in `index_v4_0.html` and other pages

### Issue 4: `docs/plots/` vs `docs/visualizations_v3/` overlap — ⚠️ DOCUMENTED

**Problem:** Two directories contain leak-rate charts with similar (but not identical) content:
- `docs/plots/plot1_leak_vs_loss.html` — core triage plot (auto-generated by `generate_dashboard.py`)
- `docs/visualizations_v3/chart_leak_vs_loss_extended.html` — extended version (by `generate_visuals_v3.py`)

Similarly:
- `docs/plots/plot4_fleet_sensitivity.html` vs `docs/visualizations_v3/chart_valve_fleet_sensitivity.html`

**Not a conflict:** The `plots/` versions are simpler, embedded in triage dashboards. The `visualizations_v3/` versions are extended/detailed for specialist use. Different audience, different detail level.

**Remediation:** No action needed. Documented in NAVIGATOR.html — `plots/` = "Core Triage Plots", `visualizations_v3/` = "Advanced Analytics".

### Issue 5: Hero pages lag behind — ⚠️ DOCUMENTED

**Problem:** 7 hero pages in `docs/heroes/` are v3.0-era audience-specific landing pages. They don't reference the current version, SSoT, or compressor configuration.

**Risk assessment:** LOW — hero pages contain valve-level data only. No compressor count, no system CAPEX, no conflicting numbers. They are excluded from stakeholder distribution.

**Remediation:** 
- Not included in any distribution bundle (documented in NAVIGATOR under "Technical Documentation")
- Future: create `src/build_heroes.py` to auto-generate from SSoT
- **Priority:** 🟢 Low — no data conflicts, no stakeholder exposure

### Issue 6: `docs/tables/` vs `outputs/tables/` — ⚠️ DOCUMENTED

**Problem:** Two directories with "tables":
- `docs/tables/` — 4 standalone HTML table pages (v3.0 era)
- `outputs/tables/` — current CSV/JSON table exports (v4.0.0 data)
- `docs/tables_v3/` — 13 CSV files used by visualizations_v3

**Potential confusion:** Which is the authoritative table data?

**Answer:** `outputs/tables/` is the current build output. `docs/tables/` is legacy presentation. `docs/tables_v3/` is intermediate data for chart generation.

**Remediation:** No rename — just documented in NAVIGATOR and STALE_FILES_AUDIT.

### Issue 7: `STAKEHOLDER_PRESENTATION.html` references v3.1.0 — ✅ ACCEPTABLE

**Context:** References are in the form "CORRECTED from 4 units in v3.1.0" and "€200k saved vs v3.1.0" — these are **corrections pointing to the old version**, not stale data. This is correct and provides audit trail.

### Issue 8: Missing SSoT reference in canonical files — ⚠️ DOCUMENTED

**Problem:** Neither `index_v4_0.html` nor `STAKEHOLDER_PRESENTATION.html` reference `data/config.yaml` as SSoT.

**Remediation:**
- NAVIGATOR.html now prominently features `config.yaml` as SSoT ✅
- Future: Add SSoT footer badge to canonical presentations
- **Priority:** 🟢 Medium
